# Feature Development Workflow

## Metadata

- ID: `feature-development`
- Version: `1`
- Status: `active`
- Goal: 将一个想法转化为经过评审、验证并完成知识沉淀的功能交付。

## 全局规则

- 各步骤按顺序执行；未满足退出条件，不得进入下一步。
- 任何范围、架构或验收标准变更都应回到对应上游步骤重新确认。
- 所有“完成”结论必须附当前任务中产生的验证证据。
- Worktree、提交、推送和部署仍受用户授权及仓库规则约束。

## 流程

### 1. Idea

- **输入**：用户想法、业务问题或机会描述。
- **输出**：一句话目标、预期价值、初始范围。
- **进入条件**：存在需要评估的新功能意图。
- **退出条件**：目标对象、问题和期望结果可以被清楚复述。

### 2. Brainstorming

- **输入**：已表述的目标、现有项目上下文、约束。
- **输出**：候选方案、权衡、推荐方案。
- **进入条件**：Idea 的目标与价值已明确。
- **退出条件**：关键方案已经比较，推荐方向获得用户认可。

### 3. Requirements / Clarification

- **输入**：获认可的方向、利益相关方约束、现有行为。
- **输出**：功能需求、非功能需求、范围外事项、验收标准。
- **进入条件**：已选定设计方向。
- **退出条件**：影响实现方向、安全、数据和兼容性的歧义均已消除。

### 4. Spec

- **输入**：完整需求与验收标准。
- **输出**：可审阅、可追溯的功能规格。
- **进入条件**：需求边界稳定且无关键歧义。
- **退出条件**：规格覆盖正常流程、边界、错误行为和验证目标，并获批准。

### 5. Architecture

- **输入**：批准的规格、现有系统结构与技术约束。
- **输出**：组件边界、接口、数据流、关键技术决策和风险。
- **进入条件**：规格已批准。
- **退出条件**：设计可实现、与现有架构兼容，风险与取舍已记录。

### 6. Plan

- **输入**：规格、架构设计、测试与交付约束。
- **输出**：按依赖排序的实施计划、文件范围、验证命令。
- **进入条件**：架构边界与接口已明确。
- **退出条件**：每项任务都有明确产物、验证方式和完成条件。

### 7. Tasks

- **输入**：批准的实施计划。
- **输出**：可独立执行和审查的任务清单。
- **进入条件**：计划覆盖全部规格要求。
- **退出条件**：任务依赖、责任边界和执行顺序无冲突。

### 8. Worktree

- **输入**：任务清单、目标分支、工作区状态与用户授权。
- **输出**：隔离且状态可确认的实施工作区，或明确记录无需新 Worktree。
- **进入条件**：任务需要实施，且已检查未提交改动与仓库约定。
- **退出条件**：实施不会覆盖既有工作，目标基线和工作目录已确认。

### 9. TDD

- **输入**：首个任务的预期行为与验收标准。
- **输出**：能够因缺失行为而失败的测试及失败证据。
- **进入条件**：工作区安全，行为可以被自动化验证。
- **退出条件**：测试以预期原因失败，而非环境或测试本身错误。

### 10. Implementation

- **输入**：失败测试、任务定义、现有代码与约定。
- **输出**：使目标测试通过的最小实现和必要文档更新。
- **进入条件**：存在有效的失败证据，或已记录无法先写测试的具体理由。
- **退出条件**：目标测试通过，改动限定在批准范围内，未隐藏已知错误。

### 11. Systematic Debugging

- **输入**：实现结果、失败测试、异常日志或行为偏差。
- **输出**：根因证据、最小修复及回归验证；若无异常则输出无需调试的记录。
- **进入条件**：出现失败、意外行为或需要确认的偏差。
- **退出条件**：根因已由证据支持，修复通过针对性回归测试；无异常时确认可进入评审。

### 12. Code Review

- **输入**：规格、计划、代码差异、测试结果和已知风险。
- **输出**：按严重度分类的评审结论及处理记录。
- **进入条件**：实现和针对性测试完成。
- **退出条件**：阻塞问题已解决或经明确接受，反馈均有技术结论。

### 13. Verification

- **输入**：评审后的实现、完整验收标准和验证命令。
- **输出**：最新测试、检查、构建或人工验收证据。
- **进入条件**：阻塞评审问题已关闭。
- **退出条件**：所有验收标准均有通过证据；未通过项会阻止完成声明。

### 14. Knowledge Capture

- **输入**：已验证实现、关键决策、失败与修复证据。
- **输出**：必要且可追溯的 patterns、decisions、failures 或 lessons 记录；若无可复用知识则记录无需沉淀。
- **进入条件**：验证已完成且结论稳定。
- **退出条件**：知识记录包含来源、适用范围、验证日期和失效条件，且不含敏感信息。

### 15. Done

- **输入**：验证证据、评审结论、知识沉淀结果和残余风险。
- **输出**：交付摘要、修改清单、验证结果、残余风险与下一步建议。
- **进入条件**：Verification 和 Knowledge Capture 的退出条件均满足。
- **退出条件**：用户可根据摘要复核交付，且没有被隐藏的未完成事项。
